# Method description

**Task.** QuantiPhy-style video question answering: each item supplies a short video and asks for
a physical quantity in a requested unit (m, cm, mm, m/s, cm/s, m/s², cm/s²). The answer must be a
single finite number followed by that unit. The evaluation set has 3,289 items over 568 videos.

**Model.** The inference base is the public checkpoint `MirroS-Lab/Code-as-World-VL-4B` at
revision `104afb28b4f1eee1d1131a50281be590e930babb` (Apache-2.0, 4B-parameter vision-language
model derived from Qwen3.5-4B). No external API, retrieval index, or ensemble is used at inference.

**Adaptation.** We use pure LoRA (r=16, α=32, dropout=0.05, bias=none) on twelve projection
modules per layer (`q_proj`, `k_proj`, `v_proj`, `o_proj`, `up_proj`, `gate_proj`, `down_proj`,
`in_proj_qkv`, `in_proj_z`, `in_proj_a`, `in_proj_b`, `out_proj`). The trainer asserts that every
trainable parameter name contains `lora_` and builds its optimizer only from those parameters, so
the base weights are never updated and no merged checkpoint exists.

**Training.** This round is one continuation epoch starting from a measured 0.863 adapter
(`weights/initial_lora_0863`). Settings: 1 epoch, learning rate
2e-5, 3,289 rows, gradient accumulation 8 (412 optimizer steps), seed 1, BF16, gradient
checkpointing, warmup fraction 0.03, weight decay 0, gradient clipping 1.0, answer-only loss (loss
is computed only on the target answer tokens; video and question tokens are masked). Training used
16 decoded frames per item and took 10,114 s (2 h 49 min). Targets are MAIN7493 pseudo-labels
generated by a 0.874-scoring Track A reference model; they are supervision for distillation, not
ground truth, and were used for training only.

**Inference.** Each item is processed independently: its own video is decoded to 32 frames sampled
at 2 fps with `max_pixels=262144`, combined with the item's question and requested unit, and passed
through the base model plus the final LoRA adapter with greedy decoding and at most 64 new tokens.
Decoding is batched per item only; no answer, context, or statistic from any other item enters the
prompt.

**Answer contract.** Every generation is validated as a whole answer before acceptance: the text
must contain exactly one finite number, the unit must be the requested unit, and generation must
stop with a known EOS token without hitting the 64-token limit; non-finite values, negative scalars
for non-negative quantities and float underflow are rejected. If the first attempt fails, one
clarification prompt in the item's own unit is issued and the second attempt is validated the same
way; if it also fails, the cell is left empty. Four of 3,289 items used the retry and none
remained unresolved.

**Validation and freezing.** Predictions and the raw generation journal were written and hashed
before any comparison with the teacher labels. A fresh-process validator replayed every recorded
attempt through the same answer-contract code and confirmed row order, metadata, adapter identity
and CSV hash without importing the primary validator. The submission CSV is byte-identical to the
frozen predictions (`1216ece8…b5b56`).

**Result and limitations.** The official portal result for this CSV is average MRA **0.866**
(Track B · Open weight, pass; S2 0.860, D2 0.887, S3 0.851, D3 0.866; invalid 0.0%; 3,010 matched
/ 0 missing), submitted 2026-10-24 11:53 Asia/Shanghai — up from 0.863 for the initializer this
continuation started from. The original server has 8 × NVIDIA RTX 6000D; the recorded jobs used
GPU 0. On 2026-10-28 the delivered code was re-executed there: the 8-question smoke run and the
full 3,289-question rerun completed with no parse failures, and all three inference artifacts (CSV,
generation journal, frozen predictions) were reproduced byte-for-byte. Training targets are
pseudo-labels from a Track A reference model (0.874), not ground truth.
