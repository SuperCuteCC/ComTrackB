Both are pure LoRA checkpoints: 496 tensors, 32,464,896 parameters each, r=16, α=32, dropout 0.05,
bias=none, on twelve projection modules per layer (`q_proj`, `k_proj`, `v_proj`, `o_proj`, `up_proj`,
`gate_proj`, `down_proj`, `in_proj_qkv`, `in_proj_z`, `in_proj_a`, `in_proj_b`, `out_proj`). They
contain no base weights and no merged tensors, so they are loaded with `PeftModel.from_pretrained`
on the base above. The final adapter is the one that produced the CSV; the initializer is a training
input and must not be stacked on it. Their earlier lineage is outside this package.

Load exactly one adapter:

```python
model = AutoModelForImageTextToText.from_pretrained(
    base, trust_remote_code=True, dtype=torch.bfloat16, attn_implementation="sdpa")
model = PeftModel.from_pretrained(model, "1.Code/weights/final_lora").eval()
```

## Generation settings

| Setting | Value |
| --- | --- |
| Backend | `transformers` 5.11.0 + `peft` 0.20.0; no vLLM, no merged weights |
| Precision / attention | bfloat16, `attn_implementation="sdpa"` |
| Decoding | greedy, `do_sample=False` |
| Max new tokens | 64 |
| Visual input | 32 frames per item, decoded at 2 fps with `max_pixels=262144`, `min_pixels=0`; the frame count is reduced to the largest even number available when a video is shorter than 32 frames |
| Prompt | the training system and user templates, `enable_thinking=False`, empty think block appended |
| Seed | 1 |
| Answer contract | whole-answer validation: exactly one finite number, the requested unit, a known EOS token, no token-limit truncation |
| Retry | at most one clarification prompt in the item's own unit; 4 of 3,289 rows used it, none stayed unresolved |

These values are recorded in `1.Code/config/inference-config.json` and hashed into every journal row
in `1.Code/outputs/generations-hf.jsonl`.

## Invocation policy

Each question is one stateless request built from that item's own video, question and requested
unit. No answer, statistic or context from another item enters the prompt; no model discussion,
voting or cross-item ensembling occurs. Labels were not read during inference
(`labels_read_during_inference: false` in `1.Code/outputs/provenance-czq.json`), and no external
service was contacted. The per-item confirmation is `5.Declaration.md`.

No dated model snapshot beyond the revision pin above was supplied, and none is inferred. The LoRA
adapters are locally produced artifacts; no public hosting URL is claimed for them, so they are
included in this package instead.
